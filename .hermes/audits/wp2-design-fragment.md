### 三 · 金额符号下沉到 format 层，调用点不再手写 ¥（ID: D-08）

总览页的 `¥{formatMoney(v)}` 全部迁到 `formatSignedMoney`（WP-1 已在 `format.ts` 提供的
`MINUS` / `YUAN` / `AMOUNT_PREFIX` / `formatMoney` / `formatSignedMoney` / `amountSign`）。
本包完成总览侧四处调用点：hero 总资产、账户余额、本月支出/收入、预算进度（含 `aria-valuetext`），
并让可见文本与 `aria-valuetext` 复用同一个格式化结果——两处各写一遍正是上一轮负数符号出错的土壤。
hero 的 `¥` 需要单独染成灯色（第二节用色规则 1），故用 `amountSign()` 只取符号、`YUAN` 常量取币种、
数字取 `formatMoney(Math.abs())` 三段拼接，符号在前、`¥` 紧跟其后，负数渲染为 `−¥12.50`（U+2212）。
支出/收入两处改为传 `kind` 而非手写 `−¥`/`+¥`：`formatSignedMoney` 在 `n < 0` 时吞掉 kind 前缀只留
一个 U+2212，因此即使 RPC 意外返回负值也不会叠出 `−−¥`。**代价**：hero 的负号用 `dim` 而非 `ink`
（灯色只留给 `¥`，符合「灯火只做点睛」），这是本包做的一个小判断。第三节「金额书写铁律」建议补一句：
符号与 `¥` 之间的空格是 bug 而非排版。

### 三 · 总览页主标题改为可见的 eyebrow 层级 h1（ID: D-49）

原结构是 `sr-only` 的 h1 + `aria-hidden="true"` 的 eyebrow `<p>`：读屏与视觉是两套文本，
且四页里只有总览的标题对视觉不可见。改为单一可见 `<h1 class="eyebrow">总览 · 二零二六年九月 本月账</h1>`，
三个分支（加载 / 错误 / 有数据）都有 h1——加载态用 `sr-only` 且**不带月份**，因为该分支会进静态
预渲染 HTML，取「今天」会造成构建日 ≠ 访问日的 hydration 不一致（同 [D-05] 的坑）。

**需要裁定的取舍**：本包**没有**把总览的 h1 做成与其余三页一致的 serif 22px。第六节的总览页线框图
明确规定 hero 是「eyebrow（月份用汉字数字）+ 灯下大数字」，没有 serif 标题行；而第六节同时规定
「区块头部统一结构：eyebrow 小标 + serif 标题」。两条对总览 hero 有张力，本包按「更具体的线框图优先」
执行，落地为审计给出的第一条方案（eyebrow 可见且作为 h1 的可见文本）。若文档包裁定以
「区块头部统一结构」为准，则总览 hero 需在灯下大数字上方补一行 serif 20–22px 的页名，
并把月份从 eyebrow 移入该行——那是**视觉变更**，不在本包范围内，未擅自执行。

### 六 · 不可点的行不加 hover：账户余额行回归规则（ID: D-07）

「各账户余额」的每一行都不可点，却带着 `hover:bg-veil` 与冗余的 `transition-colors duration-150`。
行亮一下却点不动，用户只会以为页面卡了——这正是第七节 3「反馈只给真正可点的元素」要避免的假
affordance。删除 hover、冗余过渡与随之失去意义的 `rounded-md`。本节规则**无需修改**（是回归到规则），
但值得在第八节记一句：判定依据是「元素本身是否可交互」，而不是「它在一个看起来像列表的容器里」。

### 八 · 错误态收敛为整页面板，标题随数据状态切换（ID: D-06）

总览页一次 `/api/overview` 请求失败就是整页失败，原先渲染 6 个一模一样的分区错误面板：
用户分不清是网络、鉴权还是服务端，也没有按钮（唯一出路是手动 F5），并且**整个错误态没有任何 h1**。
现收敛为 1 个整页错误面板 + 1 个可点的「重试」（接 `useApiData` 的 `reload`），标题与 h1 补齐。
第六节的骨架屏契约（第七节 2）要求加载态严格镜像真实布局，因此加载态的 h1 是 `sr-only` 的纯静态文本
（不含月份），骨架线上仍是 `SkeletonLine`。第八节 `.btn-ghost` 已是重试按钮的合适载体（灯色焦点环、
44px 触控），无需新增组件类。

### 十二 · 总览页 `<main>` 承载 skip link 锚点（ID: D-26）

根 layout 的「跳到主内容」skip link 指向 `#main`，而总览页的 `<main>` 写在 client 组件里
（`overview-client.tsx`，不是 `page.tsx`）—— 四页里只有记账/数据/设置的主壳在各自的 client 组件里，
总览则由 `page.tsx` 转交给 `OverviewClient`。本包为 `<main>` 补 `id="main"`，使该链接在总览页可用。
第十二节的「验收动作」可补一句：每页 `<main>` 必须有 `id="main"`，否则 skip link 静默失效（不报错、
不可见，只是跳不过去）。

### 十一 · 禁忌清单自检结论（本包范围内）

本包 3 个文件（`page.tsx` / `overview-client.tsx` / `api/overview/route.ts`）对第十一节十条逐条扫描：
标准色 / zinc-slate-neutral 灰阶 / `dark:` 变体 / emoji / 编号装饰均为 0 命中；
未新增任何 animation/transition（#8）；未新增 `outline-none`，重试按钮走 `.btn-ghost` 的灯色
`:focus-visible` 环（#9）；hero 与四处金额仍全部带 `.money`（#7）；灯色仍只有 `¥` 一处（#1/#2），
灯线仍只有 hero 下方一条（#3）。`npx eslint`（含 WP-1 建的禁忌类名守卫）实跑 0 问题。
